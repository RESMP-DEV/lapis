The module is organized into three layers under `lapis::session::wire`:
- Primitive layer (`wire_bytes.hpp`): big-endian `quint32`/`quint64` append/read helpers plus `Attachment` serialization that validates non-zero UUIDs.
- Message schema layer (`local_protocol.hpp`, `attention_protocol.hpp`): enumerates every frame `Kind` (hello, snapshot, text, paste, key, resize, status, attach, ready, history_request/reply, attention_snapshot/decision/retry, terminate, wheel, paste_request/result) and provides paired `encode_*`/`decode_*` functions for each struct; `Frame` + `frame()`/`take_frame()` implement a length-prefixed stream parser on a `QByteArray` buffer. Attention messages are layered on top of this envelope via an optional negotiated bit in `AttachRequest`.
- Utility layer (`update_pacing.hpp`): a stateless `UpdatePace` class that coalesces bursts of updates into a publish-per-interval cadence without debouncing.

Dependency direction is strictly inward: `attention_protocol.hpp` depends on `local_protocol.hpp`; `wire_bytes.hpp` has no intra-module dependencies. All payloads are serialized as little-endian Qt types embedded inside big-endian framing fields where specified (e.g. attachment identity). Version negotiation lives in the `version` constant and in capability bits on `AttachRequest` (hyperlinks, attention_phase, paste_transactions), allowing older clients/services to reject unknown frames.
