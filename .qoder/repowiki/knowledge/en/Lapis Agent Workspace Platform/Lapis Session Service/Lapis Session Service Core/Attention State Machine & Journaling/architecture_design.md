Three cooperating files form a layered design inside `lapis::session`:

- `attention.cpp` defines the core `State` class (with nested `Limits`, `Request`, `Pending`, `Position`, `Capabilities`, `Outcome`, `Activity`) that models the attention protocol as a deterministic finite-state machine. It enforces monotonic source epochs/sequences, bounded identities and payloads via the local `bounded()` helper, and marks itself desynchronized whenever an out-of-order or invalid transition is observed. Operations (`connect`, `disconnect`, `begin_observation`, `advance`, `reconcile`, `request`, `resolve`, `respond`, `close`) all go through `advance(position)` for sequence validation and return an `Outcome` enum rather than throwing.
- `attention_journal.cpp` provides `AttentionJournal`, an append-only wire-format writer/reader backed by `fcntl` file locking. Records start with the `LAPISATT` magic plus version byte, then carry kind/origin/seq/epoch/revision/id/request fields; every record is integrity-checked with a reflected IEEE CRC-32 computed in-process. A `Reader` struct distinguishes torn records (short read) from corrupt ones (invalid field values), and replay reconstructs `AttentionJournal::Entry` objects up to configured limits (`max_string_bytes = 64 KiB`, `max_choices = 64`).
- `attention_audit.cpp` is the thin adapter between the two: it walks `state.pending()` and emits `asked`, `decided`, `delivered`, and `resolved` journal entries, tracking which asks have already been journaled via a `JournaledAsks` map keyed by request id and revision so replay can skip them.

Dependency direction is one-way: audit depends on both state and journal; journal depends only on the shared `attention::` types declared in the header. The journal format is deliberately opaque to `State` — state never reads back its own entries, and audit is the sole producer of entries from state.
