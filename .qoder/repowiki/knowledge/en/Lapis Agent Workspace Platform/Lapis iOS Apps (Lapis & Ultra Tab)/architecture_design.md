The scope contains two independent XcodeGen targets built from `project.yml` under a shared `dev.lapis` bundle ID prefix, both targeting iOS 17.0 in dark mode.

- `Lapis/` is the primary app (`@main LapisApp`). It composes a workspace model injected via `.environment()`, then renders `AgentListView`, `AgentView`, `CategoriesView`, `NewAgentView`, `SettingsView`, plus terminal emulation through `TerminalScreen`/`TerminalViews`. Network models (workspace listing, agents, harnesses, modes, folders, mac settings, screen frames) are defined in `Gateway.swift` as Swift `Codable` structs mirroring the Python backend at `apps/remote/lapis_remote.py`; the same file also handles HTTP calls, SSE-style polling, and terminal I/O over plain HTTP inside the encrypted overlay.
- `UltraTab/` is a separate app (`@main UltraTabApp`) whose UI revolves around `DeckView` + `CardView` driven by a `DeckStore` (`@Observable @MainActor`) that follows the Mac's deck state via `DeckGateway`. `DeckGateway` implements the local `Sender` protocol used by the deck logic, exposing only the read-only `/api/deck` and submission routes.
- Both apps share the same client contract with the Mac gateway (plain HTTP, optional port, `X-Lapis-Client` header, ATS exceptions for `ts.net`), but have no shared code between them — they are sibling XcodeGen targets.
- Test bundles (`LapisTests`, `LapisUITests`, `UltraTabTests`, `UltraTabUITests`) are declared as XcodeGen targets; `UltraTabTests` is compiled together with `Cards.swift` and `Deck.swift` so it exercises the deck logic without duplicating sources.
