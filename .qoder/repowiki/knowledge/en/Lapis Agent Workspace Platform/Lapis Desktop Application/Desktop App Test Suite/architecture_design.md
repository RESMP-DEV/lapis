Flat collection of standalone test executables (one per `.cpp`/`.mm` file) that each `#include` production headers under `apps/desktop/src/` and assert in-process. Cross-cutting helpers live at the module root: `wire_fixture.hpp` provides a `WireFixture`/`WirePeer` harness that spins up a real `QLocalServer`, drives the session wire (`hello` → `snapshot` → `ready` → `resize`) and exposes `until`/`settle` event-loop polling; `clipboard_backup.hpp`, `model_change_recorder.hpp`, and `link_receiver.hpp` are small fixture utilities. Platform-specific tests (macOS only) are placed under `platform/` (`native_input_driver.{hpp,mm}`, `window_activation.{hpp,mm}`) and expose a `NativeInputDriver` facade over CoreGraphics keyboard sources. Tests split into two families: pure C++ unit tests (e.g. `accounts_test.cpp`, `keymap_test.cpp`, `cell_shapes_test.cpp`) and native Objective-C++ probes (`.mm` files like `sound_decode_test.mm`, `terminal_keys_mac_test.mm`, plus `*_probe.cpp` files such as `attention_ui_probe.cpp`, `workspace_live_probe.cpp`, `terminal_latency_probe.cpp`) that link against AppKit/CoreAudio to exercise code paths unavailable from Qt alone. There is no shared test framework binary — each file compiles its own `main()` or is picked up by the project's per-test targets.
