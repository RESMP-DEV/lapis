Two cooperating units under `lapis::desktop`:
- `accounts.{hpp,cpp}` defines the data model (`Account`, `AccountsConfig`) parsed from JSON in `~/.lapis/accounts/`, plus `AccountPool`, which ranks usable accounts by remaining quota (a global `switchAt` threshold and a five-hour short window) and exposes `choose` / `alternative` / `full` for session plan selection. `link_codex_home` merges shared Codex homes so sessions and settings stay shared across plans.
- `plan_sign_in.hpp/cpp` implements `PlanSignIn`, a Qt `QObject` with QML-bindable properties (`state`, `link`, `message`, `plan`, `machines`, `spreading`) that drives an external `plan_sign_in.py` helper via `QProcess`. It is configured through injectable `Hooks` (program resolver, link copier, browser opener, plan recorder, destination lister) and `Places` (paths to the helper and accounts directory), decoupling UI/browser/SSH concerns from the orchestration logic.

Dependency direction: `PlanSignIn` depends on `UpdaterProcess` (declared elsewhere) and on the account filesystem layout; it does not depend on `AccountPool`. Selection logic lives purely in `accounts.*`; the sign-in flow persists new accounts through the injected `Record` hook.
