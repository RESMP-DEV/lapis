Four cooperating components inside `lapis::desktop`:
- `Terminals` (terminals.{hpp,cpp}) owns one `Entry` per machine (this Mac or an ssh host), launching shells via `session::LaunchSpec`, persisting state in a `terminals.json` registry beside the workspace, and exposing machines/current/error through Qt properties/signals for QML.
- `TerminalSurface` (terminal_surface.{hpp,cpp}) is a `QQuickItem` that renders a `SessionPreview`'s `TerminalSnapshot`: it handles key/IME input, OSC 8 URL/path detection, text search, font sizing, suggestion layout, and selection. It depends on `keymap.hpp` and `workspace.hpp` (via `Q_MOC_INCLUDE`) but not on the rest of this module.
- `TabRanker` (tab_ranker.{hpp,cpp}) implements a linear softmax ranker over nine features (`work`, `request`, `unseen`, `guess`, wait time, newest, stale, turns/hour, minutes-since-turn) with three modes: `plain` (oldest-overdue-first), `learned` (fitted from `tab_away.jsonl` + `tab_away_model.json`), and `fixed` (initial guess order). Scoring runs on the GUI thread; refitting runs on a worker thread via `fit_tab_ranker`.
- `TileLayout` (tile_layout.{hpp,cpp}) represents iTerm2-style binary-split tiling of agents: inner nodes are splits (side-by-side or stacked with a ratio), leaves are agents. It provides placement, replacement, removal, neighbor lookup, reading/cycle order, and JSON serialization — used by the stage to tile category members.

Dependency direction: `TerminalSurface` and `TileLayout` are leaf utilities consumed by higher-level stage/tab code; `Terminals` and `TabRanker` own state and persist to disk under the workspace folder. All public interfaces are exposed as Qt properties/signals so QML can bind directly.
