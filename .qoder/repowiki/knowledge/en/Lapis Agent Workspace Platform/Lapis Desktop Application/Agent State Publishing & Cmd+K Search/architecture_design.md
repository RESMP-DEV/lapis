Two independent QObject-based components under lapis::desktop:
- AgentStatePublisher (agent_state.hpp/.cpp) owns a Workspace reference plus an optional NextPrompt pointer and serializes each agent's id/status/unseen/requests/reason/timing into a versioned JSON document. It coalesces rapid changes via a QTimer and writes atomically on a dedicated writer thread from QThreadPool so replacements never interleave; rate-limits output with a minimum interval between publishes.
- AgentSearch (agent_search.hpp/.cpp) precomputes lowercased title/place/category/harness/machine fields plus non-empty screen lines into Prepared entries when refresh() runs, then ranks queries by scoring every query word against those fields in order, returning up to `limit` hits with snippets.
Dependency direction is one-way: both depend on Workspace for agent discovery/screen data, but neither is read back by the rest of lapis — the published JSON is consumed externally (e.g. Ultra Tab), and search results are exposed via Q_INVOKABLE methods for Qt/QML binding.
