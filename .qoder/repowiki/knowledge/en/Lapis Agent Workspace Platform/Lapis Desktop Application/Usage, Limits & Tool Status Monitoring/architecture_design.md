Four cooperating QObject-based services share the `lapis::desktop` namespace but are loosely coupled through function-object interfaces rather than direct coupling:
- `usage_limits.{hpp,cpp}` defines `UsageProbe`, a single-shot process launcher (QProcess + optional QNetworkAccessManager for kimi's loopback server) that asks each provider CLI (`codex`, `claude`, `grok`, `kimi`, `omp`) for plan windows via their native interfaces; per-provider parsers (`codex_limits`, `claude_limits`, `grok_limits`, `kimi_limits`, `omp_limits`) produce the shared `PlanLimits` / `UsageWindow` structs. Remote probes run over `ssh -T -o BatchMode=yes` in an interactive login shell.
- `usage.hpp/cpp` composes `TokenLedger` (which walks `~/.codex/sessions` and `~/.claude/projects` transcript files, tracking per-file offsets to incrementally scan) with a pool of concurrent `UsageProbe`s driven by three timers (`limits_timer_`, `tokens_timer_`, `remote_timer_`). It exposes the UI-facing `machines()` / `meter()` properties and merges OMP accounts with CLI logins using `same_account`.
- `tool_status.hpp/cpp` polls the catalog-defined harness commands: resolves each binary via the injected `Programs` callback, then runs an optional bounded version probe with timeout, draining stdout up to `kLongestOutput` bytes into a `Running` record and publishing `rows`.
- `limit_resets.hpp/cpp` drives a multi-phase (`prepare` → `consume` → `reconcile`) state machine persisted under a folder, invoking a helper script with credentials fetched via a `Credentials` callback; it surfaces progress through `spent`/`declined`/`uncertain` signals.

Dependency direction is one-way: `usage` depends on `usage_limits`; none of the four files include each other except `usage` including `usage_limits`. All external I/O (processes, SSH, HTTP, file trees) goes through `QProcess` / `QNetworkAccessManager` plus injected `Programs`/`Agents` lambdas so tests can substitute fixtures.
