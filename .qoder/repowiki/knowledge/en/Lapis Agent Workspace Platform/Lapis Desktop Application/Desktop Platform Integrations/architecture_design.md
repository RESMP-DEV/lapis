The module is split into two concerns under `apps/desktop/src/platform/` (C++ cross-platform helpers) and three top-level files providing the macOS implementation.

- Cross-platform C++ layer (`platform/`): small, single-responsibility units exposed via header + cpp pairs — `updater_process.{hpp,cpp}` owns a child `QProcess` plus POSIX pipes to track the process group and signal completion asynchronously; `chime_file.{hpp,cpp}` reads regular files safely against symlink/device replacement without blocking workers; `reset_journal.{hpp,cpp}` serializes per-host crash/state journals with size/count/attempts limits; `published_task.hpp` provides `PublishedCallback` / `PublishedTask`, atomic publication wrappers that gate `std::function` access through an `atomic<bool>` publish/acquire protocol so Qt-owned callables are safe to move across queues.
- macOS entry points: `platform_preferences.{hpp,mm}` declares the public API (`system_reduced_motion`, `style_window_chrome`, `play_sound`) with inline no-op fallbacks behind `#ifdef Q_OS_MACOS`; `desktop_actions_mac.mm` implements all macOS-native behavior (UserNotifications, Security keychain, Carbon hotkeys, SMAppService login items, Sparkle updater bridge). The `.hpp` acts as the ABI boundary — non-macOS builds compile in the same headers but get empty inline functions.
- Dependency direction: `desktop_actions_mac.mm` depends on both the cross-platform helpers and Apple frameworks; the cross-platform C++ code depends only on Qt and `session::posix` primitives, never on AppKit/Carbon. This lets the C++ platform helpers be compiled on any target while macOS-only symbols live in the Objective-C++ file.
