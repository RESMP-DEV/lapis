Two top-level sub-trees with distinct responsibilities:
- `scripts/` is a flat collection of executable Python tooling. `check_quality.py` is the aggregator: it discovers and runs every `scripts/check_*.py` plus the unit tests under `scripts/tests/` via `unittest`, producing an aggregate JSON receipt (schema versioned by `RECEIPT_SCHEMA_VERSION`). Each `check_*.py` is self-contained and importable both as a module from `check_quality` and as a standalone CLI; cross-cutting helpers live in sibling modules such as `lapis.py`, `package_macos.py`, `runtime_digest.py`, and `release_manifest.py`. `release_manifest.py` defines durable schema objects (`ManifestSink`, gate names, Sparkle XMLNS) used across packaging scripts. `package_ultratab.py` reuses `package_macos` to build a secondary app.
- `tools/` contains non-Python artifacts. `tools/terminal_probe/` is a C++ library (`probe.hpp`) shared by `replay.cpp` and per-terminal adapters (`contour/`, `ghostty/`) built via separate `CMakeLists.txt`; each adapter declares its source list through a `sources.json` manifest. `tools/qa/` provides interactive QA harnesses (`breakit.py` driving X11 input against the real GUI, `fake_agent.py`, `history_lifecycle_probe.*`).
Dependency direction is one-way: scripts depend on repository source under `apps/`, `build/`, `.git`, etc., but nothing in the repo imports these scripts at runtime.
