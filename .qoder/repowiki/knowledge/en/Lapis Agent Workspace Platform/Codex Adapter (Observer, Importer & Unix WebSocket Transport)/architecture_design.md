Three cooperating Qt `QObject` classes form the module:
- `UnixWebSocket` (`unix_websocket.{hpp,cpp}`) is a single-threaded text transport over a Unix domain socket using Qt Network; it frames bounded messages, exposes `opened/message/failed` signals, and treats peer close as terminal. It is the only transport used by the other two components.
- `Observer` (`observer.{hpp,cpp}`) connects to a Codex TUI/app-server, classifies persistent vs temporary threads via discovery (`thread/read`, `thread/started`), buffers pre-classification events in a bounded replay queue (1024 events / 1 MiB), reconciles resume/read with source replay, and forwards approvals and structured user-input answers into `session::attention::State`. It tracks qualified binary digests and exposes read-only hook inventory/runs for the UI.
- `Importer` (`importer.{hpp,cpp}`) is an independent onboarding client: it opens its own dedicated server connection, detects Claude migration items, validates bounded results, submits exact `SESSIONS` payloads by position, and reports per-item progress/failure plus completion by Codex import ID. It never retries failed/malformed/timed-out tasks.

Dependency direction is one-way: both Observer and Importer depend on `lapis::session` and `lapis_project_options`; they do not depend on each other. The CMake target `lapis_codex_adapter` is a static library built against Qt 6 Core/Network, with three separate test executables wired through `add_test`. The PIMPL idiom (`class Impl; std::unique_ptr<Impl> impl_`) hides all internal state from consumers.
