Two cooperating components under `lapis::claude`:
- `Observer` (observer.hpp/.cpp) is a `QObject` owning a private observation channel; it accepts hooks either from a `QLocalSocket` (`Transport::local_socket`) or as pre-authenticated JSON objects pushed by the session service over the terminal (`Transport::terminal`). It tracks per-session state, computes background-work details, coalesces `changed()` signals on the event loop, and exposes `launchArguments` for spawning Claude.
- The relay (hook_relay.hpp/.cpp) is a standalone executable invoked by Claude Code. It reads one JSON frame from STDIN within `relay_deadline_ms`, validates identity fields, derives an `in_flight` count from `background_tasks`/`session_crons`, serializes a `{nonce, event}` frame, and writes it to the observer's `QLocalSocket`. Failures are fail-open (return 0), never leaking errors to Claude.
- Shared contract constants live in `hook_relay.hpp`: `hook_event_names` lists the nine registered Claude events, `relay_identity_fields` / `relay_derived_fields` define the wire shape, and `relay_contract = "2"` gates inclusion of derived fields so older services get the legacy shape.
- Build produces a static library `lapis_claude_adapter` linked against Qt6 Core/Network and `lapis_attention`; tests compile into `lapis_claude_observer_tests` with a 60s timeout (180s under TSan).
